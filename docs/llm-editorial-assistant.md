# Journal Studio 写作模型

Journal Studio 只有一套写作口径。排版、润色、摘要和翻译都从 `server/prompts/editorial-assistant.cjs` 读取同一个系统提示词，再叠加各自的任务说明。前端不保存第二份提示词，避免页面更新后出现两套风格。

## 能做什么

- 排版：整理 Markdown 标题、段落、列表和代码块。
- 润色：删掉宣传腔、机械排比和常见 AI 套话，保留作者原来的判断。
- 摘要：从现有正文里提炼 60–120 字摘要与 3–6 个标签。
- 翻译：中英互译，保留代码、路径、产品名和 Markdown。

模型返回建议稿，编辑器不会直接覆盖正在写的内容。采用前会显示标题、摘要和正文预览。

## 共同边界

提示词明确禁止补造人名、日期、数字、结果、用户反馈和实现状态。输入里没有的内容必须留空或标记资料不足。中文写作使用项目复盘口吻，避免“赋能、打造、生态闭环”等宣传词，也不用“这不仅是……更是……”一类公式句。

输出固定为 JSON：

```json
{
  "title": "",
  "standfirst": "",
  "body": "",
  "tags": []
}
```

## 配置

```env
LLM_API_KEY=your-key
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=your-openai-compatible-model
```

服务端只调用 `${LLM_BASE_URL}/chat/completions`。密钥不会发送到浏览器，状态接口只返回是否已配置、模型名和接口地址。单次输入上限为 45,000 字符，请把很长的文章拆成几段处理。

没有配置模型时，写作、预览、草稿和发布都不受影响。四类 AI 操作都会提示先配置模型，不覆盖原稿，也不把本地规则包装成模型结果。建议稿需要手动采用，之后可以撤销；空响应、格式错误、网络失败和超时都保留原文。
